# 现场服务

服务案例（Case）是**一次沟通**；有些故障必须有人**到现场**——那就是一张
**工单**：一个工程师、一个现场、一次上门。

现场服务在 HotCRM 中增加了两类记录，以及派工使用的看板：

| 记录 | 是什么 |
| --- | --- |
| 🖥️ **设备** | 安装在客户现场的一台设备——属于哪个客户、装在哪个地址、什么型号、序列号是多少、保修到什么时候。 |
| 🔧 **工单** | 针对这台设备的一次上门——谁去、什么时候去、做了什么、谁签的字、这次是否收费。 |

## 设备 — 你的装机量

产品目录里的产品是**型号**；设备是**具体那一台机器**：客户车间里真实存在的
那一台。

| 字段 | 为什么重要 |
| --- | --- |
| **客户** / **现场联系人** | 谁的设备，以及工程师出发前该给谁打电话 |
| **产品 / 型号**、**序列号** | 它是什么——序列号是客户在电话里念给你听的东西，因此支持全局搜索 |
| **安装地址** / **安装坐标** | 工程师实际要开车去的地方；坐标同时驱动**地图**视图 |
| **安装日期** | 什么时候装的 |
| **保修开始 / 截止** | 保修窗口——决定这次上门是否免费 |
| **在保** | 系统自动维护（见下） |
| **服务合同** | 出厂保修之外的延保 |

### 保修的自动推算

只填安装日期、不填保修日期时，HotCRM 会自动按安装日期起算 **12 个月**出厂
保修。实际保修不同（延保、特殊约定）时，直接改这两个日期即可。

每天的定时任务会把已过保设备的**在保**标记清掉，并通知设备负责人——不会
因为没人打开记录，保修到期就悄悄溜过去。

### 设备视图

- **设备状态看板** — 按已安装 / 维修中 / 已停用 / 已报废分组。
- **设备分布地图** — 机器实际在哪。
- **保修到期日历** — 按日期铺开的到期情况，让续保谈判发生在过保之前。
- **已过保设备** — 需要收费的那部分装机量。
- **维修中设备** — 当前停机的设备。

## 工单

### 从服务案例开单

电话是客服接的。在任何未关闭的服务案例上点**创建服务工单**，客户、联系人和
故障描述会被直接带到新工单上，并把两条记录关联起来。客服只需要补两件案例
本身不知道的信息：**工单类型**和**现场优先级**。

案例随后变为*等待支持*——在上门完成之前它保持打开，客户不会被晾在半路。

### 响应承诺

工单一保存就会得到**响应截止时间**：

| 优先级 | 承诺响应时限 |
| --- | --- |
| 🔴 **紧急** | 4 小时 |
| 🟠 **高** | 8 小时 |
| 🟡 **普通** | 24 小时（当天） |
| ⚪ **低** | 72 小时 |

- 把工单升级到更高优先级会**把截止时间往前拉**，从升级那一刻重新计算。
- 手工填写的截止时间始终优先——你对客户口头承诺过具体时间时用它。
- 承诺的是**有人响应**，不是修完：工单一旦离开*新建*状态，计时就停止。

每小时的定时任务会把已过响应截止时间、却仍无人响应的未完成工单标记为
**响应超时**，并通知**服务主管**（即工单负责人）。该任务不会改写工单状态——
排期和派工始终由调度决定。

### 工单的 8 种状态

| 状态 | 含义 |
| --- | --- |
| ⚪ **新建** | 已开单，尚未指派 *(默认)* |
| 🔵 **已排期** | 已有上门时间窗口 |
| 🟣 **已派工** | 工程师在路上 |
| 🟠 **进行中** | 正在现场施工 |
| 🟡 **挂起** | 卡住了——等配件，或等客户 |
| 🟢 **已完工** | 上门做完并已签字 |
| 🟢 **已关闭** | 计费和回访也完成了 |
| ⚫ **已取消** | 不做了 |

处于*已完工*的工单仍留在未关闭队列上——它还欠一笔费用和一次满意度评分。

## 派工

指派**现场工程师**并填上**计划开始 / 结束**，这次上门就会出现在两个看板上：

- **派工日历** — 所有已排期的上门，按紧急程度着色，调度就看这个。
- **工程师排期** — 同样的上门，但**每位工程师一条泳道**，用来回答"周四谁
  有空、这个人当天已经跑几家了"。

如果把某人排进与他自己另一次上门重叠的时间窗，工单会被标记**排期冲突**。
这是提醒而不是拦截——调度有时会故意把同一个工业园的两单排在一起。

两个队列让看板真正可用：

- **待派工** — 还没指派人的，紧急优先。
- **响应临期** — 未关闭、无人响应、按截止时间最近排前。

## 免费还是收费 — 派单前就定下来

工单填上设备后，HotCRM 会在**保存时**读取该设备的保修状态，并写入工单：

- **保修状态** — *保修期内* / *已过保* / *未知*
- **收费工单** — 设备已过保时自动勾选

正因为是保存时算的，费用在**派人之前**就写在记录上——这正是关键。**收费
工单**队列列出所有需要收费的上门，确保没有一单在客户不知情的情况下出发。

工单一旦关闭或取消，计费结论就被**冻结**：之后设备保修到期，不会再改写一单
已经做完的工作的商务条款。

## 完工登记

工单上的**完工登记**用一张表单收齐所有信息：

| 内容 | 是否必填 |
| --- | --- |
| **服务内容** | 必填——没有它无法完工 |
| **签字人**（现场验收人姓名） | 必填 |
| **更换配件**、**工时**、**服务费用** | 选填 |

客户的手写**签字**在记录的**完工**页签上采集。没有签字也能完工，只会记录一条
提醒——不会因为平板没网或客户拒绝签字就把工程师卡在现场。

## 回访

工单**已完工**一天后，HotCRM 会提醒服务主管致电现场并登记**满意度评分**——
和服务案例现在用的是同一套回访机制，只是跑在上门这件事上。

## 权限

| 角色 | 设备 | 工单 |
| --- | --- | --- |
| **客服专员**（受理 + 派工） | 可读、可维护 | 可开单、派工，可编辑任意工单 |
| **现场工程师** | 可读，可就地更正现场发现的错误信息 | 可看全部看板；只能编辑指派给自己的工单。计费字段只读，内部备注不可见。 |
| **销售代表 / 销售经理** | 只读——客户已有哪些设备属于续约背景信息 | 无权限 |
| **系统管理员** | 全部权限 | 全部权限 |

## 暂不包含

以下能力有意留在范围之外，并记录在需求档案中：

- **自动选派工程师** — 技能匹配、路线优化、考虑路途时间的排程。当前派工是
  人工在日历上完成的。
- **多次上门与多人班组** — 一张工单对应一次上门。
- **配件库存** — 配件以文本形式记录在完工信息里，不核销产品目录中的库存。
- **即时通讯渠道接入**（例如微信群机器人） — 工单可以记录*即时通讯*这个
  报修渠道，但对接某个具体的通讯平台属于客户侧扩展，不进入标准产品。
