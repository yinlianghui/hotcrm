# 現場服務

服務工單（Case）是**一次溝通**；有些故障必須有人**到現場**——那就是一張
**工作單**：一位工程師、一個現場、一次到府。

現場服務為 HotCRM 增加了兩類記錄，以及派工使用的看板：

| 記錄 | 是什麼 |
| --- | --- |
| 🖥️ **設備** | 安裝在客戶現場的一台設備——屬於哪個客戶、裝在哪個地址、什麼型號、序號是多少、保固到什麼時候。 |
| 🔧 **工作單** | 針對這台設備的一次到府——誰去、什麼時候去、做了什麼、誰簽的名、這次是否收費。 |

## 設備 — 你的裝機量

產品目錄中的產品是**型號**；設備是**具體那一台機器**：客戶廠房裡真實存在的
那一台。

| 欄位 | 為什麼重要 |
| --- | --- |
| **客戶** / **現場聯絡人** | 誰的設備，以及工程師出發前該打給誰 |
| **產品 / 型號**、**序號** | 它是什麼——序號是客戶在電話裡念給你聽的東西，因此支援全域搜尋 |
| **安裝地址** / **安裝座標** | 工程師實際要開車去的地方；座標同時驅動**地圖**檢視 |
| **安裝日期** | 什麼時候裝的 |
| **保固開始 / 截止** | 保固期間——決定這次到府是否免費 |
| **保固中** | 系統自動維護（見下） |
| **服務合約** | 原廠保固之外的延長保固 |

### 保固的自動推算

只填安裝日期、不填保固日期時，HotCRM 會自動以安裝日期起算 **12 個月**原廠
保固。實際保固不同（延保、特殊約定）時，直接修改這兩個日期即可。

每天的排程作業會清除已過保設備的**保固中**標記，並通知設備負責人——不會
因為沒人開啟記錄，保固到期就悄悄過去。

### 設備檢視

- **設備狀態看板** — 依已安裝 / 維修中 / 已停用 / 已報廢分組。
- **設備分佈地圖** — 機器實際在哪。
- **保固到期日曆** — 依日期攤開的到期情況，讓續保洽談發生在過保之前。
- **已過保設備** — 需要收費的那部分裝機量。
- **維修中設備** — 目前停機的設備。

## 工作單

### 從服務工單開單

電話是客服接的。在任何未結案的服務工單上點**建立服務工作單**，客戶、聯絡人
與故障描述會直接帶到新的工作單上，並將兩筆記錄關聯起來。客服只需要補上兩件
服務工單本身不知道的資訊：**工作類型**與**現場優先順序**。

服務工單隨後轉為*等待支援*——在到府完成之前它保持開啟，客戶不會被晾在半路。

### 回應承諾

工作單一儲存就會取得**回應截止時間**：

| 優先順序 | 承諾回應時限 |
| --- | --- |
| 🔴 **緊急** | 4 小時 |
| 🟠 **高** | 8 小時 |
| 🟡 **普通** | 24 小時（當天） |
| ⚪ **低** | 72 小時 |

- 將工作單升級到更高優先順序會**把截止時間往前拉**，自升級當下重新計算。
- 手動填寫的截止時間永遠優先——你對客戶口頭承諾過具體時間時使用它。
- 承諾的是**有人回應**，不是修完：工作單一旦離開*新建*狀態，計時就停止。

每小時的排程作業會將已過回應截止時間、卻仍無人回應的未完成工作單標記為
**回應逾時**，並通知**服務主管**（即工作單負責人）。該作業不會改寫工作單
狀態——排程與派工始終由調度決定。

### 工作單的 8 種狀態

| 狀態 | 含義 |
| --- | --- |
| ⚪ **新建** | 已開單，尚未指派 *(預設)* |
| 🔵 **已排程** | 已有到府時間區間 |
| 🟣 **已派工** | 工程師在路上 |
| 🟠 **進行中** | 正在現場施工 |
| 🟡 **暫停** | 卡住了——等零件，或等客戶 |
| 🟢 **已完工** | 到府完成並已簽名 |
| 🟢 **已結案** | 計費與回訪也完成了 |
| ⚫ **已取消** | 不做了 |

處於*已完工*的工作單仍留在未結案佇列上——它還欠一筆費用與一次滿意度評分。

## 派工

指派**現場工程師**並填上**預計開始 / 結束**，這次到府就會出現在兩個看板上：

- **派工日曆** — 所有已排程的到府，依緊急程度著色，調度就看這個。
- **工程師排程** — 同樣的到府，但**每位工程師一條泳道**，用來回答「週四誰
  有空、這個人當天已經跑幾家了」。

若將某人排進與他自己另一次到府重疊的時間區間，工作單會被標記**排程衝突**。
這是提醒而非阻擋——調度有時會刻意把同一個工業區的兩單排在一起。

兩個佇列讓看板真正可用：

- **待派工** — 尚未指派人員，緊急優先。
- **回應臨期** — 未結案、無人回應，依截止時間最近排前。

## 免費還是收費 — 派單前就定案

工作單填上設備後，HotCRM 會在**儲存時**讀取該設備的保固狀態，並寫入工作單：

- **保固狀態** — *保固期內* / *已過保* / *未知*
- **收費到府** — 設備已過保時自動勾選

正因為是儲存當下計算的，費用在**派人之前**就寫在記錄上——這正是關鍵。
**收費工作單**佇列列出所有需要收費的到府，確保沒有一單在客戶不知情的情況下
出發。

工作單一旦結案或取消，計費結論即被**凍結**：之後設備保固到期，不會再改寫
一單已經做完的工作的商務條件。

## 完工登錄

工作單上的**完工登錄**用一張表單收齊所有資訊：

| 內容 | 是否必填 |
| --- | --- |
| **服務內容** | 必填——沒有它無法完工 |
| **簽名人**（現場驗收人姓名） | 必填 |
| **更換零件**、**工時**、**服務費用** | 選填 |

客戶的手寫**簽名**在記錄的**完工**頁籤上擷取。沒有簽名也能完工，只會記錄一則
提醒——不會因為平板沒網路或客戶拒簽就把工程師卡在現場。

## 回訪

工作單**已完工**一天後，HotCRM 會提醒服務主管致電現場並登錄**滿意度評分**——
與服務工單目前使用的是同一套回訪機制，只是跑在到府這件事上。

## 權限

| 角色 | 設備 | 工作單 |
| --- | --- | --- |
| **客服人員**（受理 + 派工） | 可讀、可維護 | 可開單、派工，可編輯任何工作單 |
| **現場工程師** | 可讀，可就地更正現場發現的錯誤資訊 | 可看全部看板；只能編輯指派給自己的工作單。計費欄位唯讀，內部備註不可見。 |
| **業務代表 / 業務主管** | 唯讀——客戶已有哪些設備屬於續約背景資訊 | 無權限 |
| **系統管理員** | 全部權限 | 全部權限 |

## 暫不包含

以下能力刻意留在範圍之外，並記錄在需求檔案中：

- **自動選派工程師** — 技能媒合、路線最佳化、考量交通時間的排程。目前派工是
  人工在日曆上完成的。
- **多次到府與多人班組** — 一張工作單對應一次到府。
- **零件庫存** — 零件以文字形式記錄在完工資訊中，不沖銷產品目錄的庫存。
- **即時通訊管道介接**（例如 LINE 或微信群機器人） — 工作單可以記錄*即時通訊*
  這個報修管道，但介接某個特定通訊平台屬於客戶端擴充，不進入標準產品。
